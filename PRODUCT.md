# Product

## Register

product

## Users

People facing a broken household appliance who need a calm, understandable way to make safe physical observations while an AI reasons through the diagnosis. In the hackathon demo, the user is diagnosing one fictional washing machine that will not drain. Judges must be able to understand and operate the product immediately without credentials.

## Product Purpose

Clunk is a shared visual repair bench for a person and a browser agent. The person reports what they can physically observe; the agent uses a small set of WebMCP tools to update the same visible appliance model, diagnostic state, safe checks, likely causes, compatible fictional parts, and escalation path. Success means the five-second promise is obvious: “Tell it what’s broken. It shows you what to check and finds the exact part.”

## Brand Personality

Simple, instantly understandable, clean. The interface should feel calm and exact under pressure, with the visual restraint, generous spacing, strong hierarchy, and direct interaction patterns of the OpenAI Developers showcase.

## Anti-references

- Busy enterprise dashboards that make diagnosis feel like data administration.
- Decorative workshop skeuomorphism, grunge, blueprint clichés, or faux hand-drawn diagrams.
- Neon “agent” interfaces, chat-first layouts, gradients, glass effects, and generic AI styling.
- Dense prose, nested cards, ambiguous controls, or hidden safety boundaries.
- Any visual or copy that implies real-world diagnosis or compatibility for the fictional demo appliance.

## Design Principles

1. Make the next safe action obvious before exposing detail.
2. Keep the human, agent, and appliance synchronized in one shared state.
3. Show reasoning through visible state changes, not explanatory walls of text.
4. Treat safety and uncertainty as core product behavior.
5. Make the demo model and fictional compatibility limits impossible to miss.

## Accessibility & Inclusion

Target WCAG 2.2 AA. Support keyboard-only operation, visible focus, semantic landmarks, screen-reader status announcements, color-independent component highlighting, 44px touch targets, responsive mobile layouts, and a reduced-motion mode. Safety instructions must use plain language and must never rely on color alone.
