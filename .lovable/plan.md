# Diagnosis: stale preview and "files are missing" on publish

## What the Lovable build log actually shows

Lovable's hosted pipeline runs its own sequence (checkout, install, typecheck, build). The build step failed with:

```text
=== build ===
error: Script not found "build:dev"
frontend build failed.
```

Notes from the same log:

- Install succeeds; Lovable installs with `bun install` and migrated the repo's `package-lock.json` into `bun.lock`.
- Typecheck produced no errors.
- The only failure is the missing `build:dev` npm script. Lovable's frontend builder invokes `build:dev` (the development-mode Vite build used for preview/publish artifacts), which does not exist in this repository's `package.json` — it only defines `build`.

Because that command exits non-zero, no `dist/` artifact is produced, so the preview keeps serving the last successful build (stale) and the published deploy has no files to serve ("files are missing"). Local `npm ci` / `npm run build` / the verification suite pass because they never call `build:dev`.

## Smallest portable fix

Add one script to `package.json`:

```json
"build:dev": "vite build --mode development"
```

That is the entire change. It is portable, standard Vite, adds no dependency, changes no config, and does not affect local commands, tests, or CI. This is the exact script name and shape the Lovable Vite template ships with.

## Optional secondary items (not required for the fix)

- `.lovable/project.json` still records `template: tanstack_start_ts_current` from the original scaffold while the repo is now static Vite + React. This did not cause the failure and should be left alone unless hosting misbehaves after the script fix.
- Two lockfiles now coexist (`package-lock.json` committed, `bun.lock` generated by Lovable's install). Harmless; if you want determinism on the hosted side, keep only `package-lock.json` in git and let Lovable migrate it, which is the current behavior.
- Consider whether `build` should keep `tsc --noEmit &&`. It is fine, but if a future type error appears only in the hosted toolchain version, publishing would break again. `build:dev` deliberately skips typecheck, matching Lovable's expectations.

## Verification after the change

1. Confirm `npm run build:dev` produces `dist/index.html` locally.
2. Re-sync the commit and check the Lovable build log shows `build OK`.
3. Publish and load the top-level URL; the app should render instead of the missing-files page.

No files were edited, no commit created, and no project settings changed during this diagnosis.
